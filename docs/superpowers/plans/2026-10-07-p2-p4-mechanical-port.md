**Goal:** Take all 32 pinned fixtures to zero parser warnings + byte-identical written
output by porting py-armodel's reader/writer methods family-by-family from the persistent
queue.

**Architecture:** The class-family queue (`docs/plan/sync-todo/Group1.md` … `Group36.md`,
1,904 rows) is the single source of work items; the `sync-autosar-class` skill owns the
per-family 9-step TDD loop. This plan owns the *phase-level* orchestration the skill does
not: batch sequencing (fixture clusters, roadmap §5.1), graduation accounting, regression
discipline, docs hygiene, and the phase exit gate. It deliberately does not duplicate the
per-family procedure or the queue rows.

**Tech Stack:** Rust (quick-xml 0.42, slotmap, thiserror), `tools/py2rust` generator
(`--emit-port-checklist` / `--check`), pinned py-armodel at `tools/py2rust/PY_ARMODEL_VERSION`
(32 fixtures), pytest-free verification via `cargo test` harness gates.

```rust
// src/reader/arxml_reader/common.rs — one Rust fn per py method, /// py `readXxx.` provenance
/// py `readARElement` — the ARElement chain level: ARElement adds no own
/// payload, so this passes the Identifiable payload through.
pub(super) fn read_ar_element(
    &mut self,
    element: &Node,
    document: &mut Document,
) -> Result<IdentifiablePayload, ParseError> {
    self.read_identifiable_payload(element, document)
}
```

```rust
// src/writer/arxml_writer/common.rs — writer order extracted from py's writer body,
// never assumed from the reader (Rule 0001.4)
pub(super) fn write_ar_element<W: Write>(
    &self,
    writer: &mut Writer<W>,
    element: BytesStart<'_>,
    attrs: IdentifiableAttrs<'_>,
    parts: IdentifiableParts<'_>,
    document: &Document,
) -> Result<(), WriteError> {
    let mut element = element;
    self.write_identifiable_attributes(
        &mut element,
        attrs.checksum,
        attrs.timestamp,
        attrs.uuid,
    );
    writer.write_event(Event::Start(element))?;
    if let Some(short_name) = attrs.short_name {
        write_text_element(
            writer,
            "SHORT-NAME",
            BytesStart::new("SHORT-NAME"),
            Some(short_name),
        )?;
    }
    self.write_identifiable_parts(writer, parts, document)
}
```

## Batch → queue accounting rule (applies to Tasks 2–6)

The queue is dependency-first by class; batches are fixture clusters. They reconcile through
each family row's fixture set (every row names the fixtures it exercises): a family belongs
to the first batch that names one of its fixtures. "Primary queue groups" in each task are
the expected starting groups — if a family session discovers the fixture depends on an
unported class from another group, port that class's row first (the queue's dependency order
already encodes this; never skip a callee, Rule 0012.5).

## Regression discipline (whole phase)

- The harness is cumulative: a batch must never regress an earlier fixture; the
  model-equality gate (all 32) stays green throughout every session.
- Fixtures are verbatim upstream artifacts — never edited (Rule 0006.1). The Rust side
  conforms to the fixtures; py divergences are recorded in the family row, not reconciled.
- The py-armodel pin (`tools/py2rust/PY_ARMODEL_VERSION`) is read-only for the whole phase
  (Rule 0013).
